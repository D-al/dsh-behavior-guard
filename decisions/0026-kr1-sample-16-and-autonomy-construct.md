# ADR-0026：KR1 样本量改为 16（有据）+ 自主构念缺口登记

- 状态：accepted
- 日期：2026-11-22
- 决策者：用户（显式批准："改16，然后重新思考一下KR1有没有高效的完成手段"）
- 决策层级：重要决策 I（改变验收判据，有统计依据）
- 支撑决策：ADR-0020（KR 体系落地）、ADR-0022（阈值来自实测）

## Context（背景）
KR1 写"10 任务完整闭环"，追溯发现**无依据**：
- `docs/GOAL_STATEMENT_V3_1_20261122.md`（13:15）只写 10，无论证；自己还记着"阈值口径不一致（A5=7天/KR1=10任务）"
- `docs/SCIENTIFIC_MEASUREMENT_20261122.md`（12:28，早 47 分钟）用 `n ≥ 2(zσ/δ)²`，
  σ=10%、检测 10% 变化 → **n≥16**，并明确写"凑够样本量：≥16 个 task 会话"
- 10 是写目标时顺手定的，与 KR4 的 30s 时间盒同类（ADR-0022 已处理过那个）

**更根本的构念缺口**（本次追溯发现）：
- 已完成 4 张闭环（S18/S19/S21/M10）都是**外部开发 agent 手动逐条发命令**
  （`--claim`→`--verify`→`--apply`）触发的
- `A5 自己走（常驻闭环：读图→选任务→执行→验收→写回→反思→下一轮）` 仍是 **backlog**——
  真正的自主闭环机制尚未建成
- KR1 的"干预≤2"只统计 `human_intervention`/`escalate` 事件；外部命令打点用的是
  `task_done`，**不构成 intervention** → 4 张卡实际外部干预 12 次（4×3），判据却看到 0
- 38 张历史 done 卡无 live 打点，是"机制存在"证据，不是"机制被自主使用"——不算 KR1

## Options
| 方案 | 做法 | 结论 |
|---|---|---|
| A 维持10标软门槛 | 不改数字，标注非统计结论 | 已被用户否决 |
| B 改16（选中）| 用项目自己的统计下限 | ✅ 有据；但须同时登记构念缺口 |
| C 改结构 | 10闭环+16总样本双口径 | 更复杂，暂不取 |

## Decision
1. KR1 阈值 10 → **16**（`goal_verify.py` 与 STRATEGY.md §2.1 同步），依据 `2(zσ/δ)²` 统计下限。
2. 当前进度诚实标注：**4/16**（不是"差 12 张卡"那么简单——见下）。
3. **登记构念缺口（本次只登记，不改判据）**：KR1 目前测的是"外部 agent 能驱动闭环 16 次"，
   不是"系统自己走 16 次"。这一缺口写进本 ADR 与 STATUS.md，**但本次不添加 A5 硬闸**——
   是否加" A5 未 done 则 KR1 N/M"须用户另行拍板（已作为决策项呈交）。
4. 高效手段另开探索（本次不拍板）：真正自主需建 A5 常驻闭环；或改判据承认"外部触发的确定性闭环"
   是另一种构念——**不得两者混称**。

## Counter-evidence（反证）
- **反对改16**：样本量公式针对"检测 10% 能力变化"，KR1 是二值判据（闭环成功/失败），不完全适用。
  → 承认：16 是保守代理，不是精确推导；但它至少优于无据的 10，且不低估。
- **反对加A5硬闸**：会让 KR1 长期 N/M（A5 是大工程）。
  → 这是**feature**：N/M 是诚实状态，比"用外部驱动冒充自主然后 PASS"好。
- **翻案条件**：若用户明确把 KR1 重新定义为"外部驱动的确定性闭环可靠性"（而非"自主"），
  则撤 A5 硬闸并重开 ADR；判据与命名必须同步改，不得只改判据。

## Consequences
- 正面：阈值有据；构念缺口显性化；防"假自主 PASS"。
- 负面：KR1 预计长期 N/M 直到 A5 建成；工作量实质增加（4→16 需 12 次完整闭环 + A5）。
- 验证：goal_verify KR1 报 4/16；A5 未 done 时强制 N/M；全门禁绿。
