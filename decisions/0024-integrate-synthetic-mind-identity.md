# ADR-0024：融合"合成心智"身份与双轴战略——机制、方向、边界三层归一

- 状态：accepted
- 日期：2026-11-22
- 决策者：用户（显式要求："重新融合一下合成心智和现在的战略目标；整理更新所有md文档"）
- 决策层级：关键决策 K（统一身份叙事与战略结构）
- 支撑决策：ADR-0020（KR 体系）、ADR-0023（双轴融合）

## Context（背景）
科技树按 KR 重绘后，活文档里出现两层看似冲突的表述：
- README.md:3 / lineage/IDENTITY.md / lineage/ORIGIN.md：**"合成心智"是身份**——
  "一个 35B + 一套确定性脚手架，合成比模型本身可靠得多的心智；权重一个字节没动，变的是它外面的脑区"
- STRATEGY.md v3.1 + ADR-0023：**"持续成长的计算体"是目标**，双轴=体系智能进化轴 + 6KR 护栏轴

初看像"旧目标（合成心智）被新目标（计算体）取代"——但核实后发现这是**误读**：
"合成心智"从来不是被验收的目标，它是**机制与身份的描述**（权重不动、靠 harness 外置器官变聪明）。
ADR-0023 的"进化轴=不改权重让体系更智能"与它**完全同构**——同一件事的两种说法。

核实事实：
- README.md:3 的合成心智定义 = "权重一个字节没动，变的是它外面的脑区"
- STRATEGY.md §1 进化轴 = "权重零改，靠 harness 让同一模型表现更好"
- 两者指向同一机制：harness 层的确定性脚手架 / 外置器官
- 旧"六项能力指标"（已被 KR 取代，ADR-0020）才是真正被替换的东西——不是"合成心智"这个身份

## Options
| 方案 | 做法 | 结论 |
|---|---|---|
| A 删除合成心智表述 | 活文档全改成"计算体" | ❌ 抹掉身份与五层依赖链叙事；且概念同构，没必要 |
| B 并列两套目标 | 保留各自表述不解释关系 | ❌ 读者困惑"到底哪个是目标"——正是本次要解决的 |
| C 三层归一（选中）| 合成心智=机制/身份，计算体=方向，KR=边界；写清映射 | ✅ 不删历史、消除混淆、接上 ADR-0023 双轴 |

## Decision
三层归一（写入 STRATEGY.md §1 与各活文档）：
1. **身份/机制层 = 合成心智**：怎么让体系更聪明——hook 35B + 外置确定性器官，权重零改。
   这是"我们是什么"，不是被验收的目标。五层依赖链（物质→调优→脑→合成→探索）作为**谱系叙事**保留。
2. **方向层 = 持续成长的计算体**：往哪进化——体系智能不断提升（ADR-0023 进化轴），
   且不丢失可控、可关闭、可回滚。这是"我们去哪"。
3. **边界层 = 六个 KR**：不许怎么走（ADR-0023 护栏轴）。这是"验收什么"。
4. **映射澄清**：
   - 被 KR 取代的是**旧六项能力指标**（ADR-0020），**不是**合成心智身份——文档必须写清这个区分
   - 合成心智的"外置器官"就是 ADR-0023 进化轴的建设机制（悬空认知卡 = 新一代器官）
   - Identity 文档讲的是"机制与来历"，Strategy 讲的是"方向与验收"——不互相覆盖
5. **文档更新范围**：只更活文档（STRATEGY / README / decisions/README / lineage/IDENTITY / lineage/ORIGIN）；
   历史实验/诊断文档（docs/ 下 116 个带日期的）**不动**——它们是可追溯证据，改写即破坏审计链。

## Counter-evidence（反证）
- **最强反对**：保留"合成心智"会让人误以为旧目标还在，重开"双轨验收"。
  对冲：所有活文档必须显式写"它是身份/机制，不是验收目标；验收只看 §2.1 KR + §2.2 guardrail"。
- **第二反对**：三层归一是文字游戏，没有操作差异。
  对冲：操作差异明确——决策时按层判断：改机制看合成心智谱系，定方向看 STRATEGY 进化轴，判达标看 KR。
- **翻案条件**：若用户明确想让"合成心智"退场为纯历史名词，则改为"前身"表述并重开 ADR。

## Consequences
- 正面：身份与战略不再打架；旧文档不删改写；悬空认知卡有了谱系解释（新一代外置器官）。
- 负面：读者需理解三层结构；README 开头需加一段导航，否则仍会误读。
- 验证：5 个活文档的"合成心智"表述均带三层定位；citation_guard 与全门禁绿。
