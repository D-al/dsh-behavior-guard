# ADR-0017：短期收口后先建长期地基（GWT → FEP），再积累中期目标

- 状态：accepted
- 日期：2026-11-18
- 决策者：用户（路线顺序）+ 本会话实现验证

## Context（背景）
短期四目标（spec 分类 / Critic 去同源 / test-time 自适应 / 真实回归）全部完成。
ROADMAP 原顺序是短期 → 中期（技能进化/可控遗忘/情景检索/会话树）→ 长期（GWT 总线/FEP/BDI）。
但两个事实改变了最优顺序：
1. 波次表自己写着"GWT 状态总线把散落状态缝成单一认知流；技能提炼才能拿到完整证据"——
   总线是中期目标的**前置**，却与中期并列写在同一波，依赖方向没在顺序里体现。
2. 中期目标多是数据积累型（outcome 63 条、trace 3200+ 已在增长，早晚做成本一样），
   地基是结构型（接口越晚定，后面接的模块越要返工重接）。
3. 骨架已半建：`s.frame`（五元组）/`s.bdi`/`s.evidence`/`s.verifyRan` 已在同一个 state 对象，
   缺的只是统一只读视图 + 消费者改从它取数——低风险改动。

## Decision（决定）
调整执行顺序：先建两块长期地基（① GWT 共享状态对象 → ② FEP 预期闭环），验证通过后，
再在此之上逐步积累原中期目标。独立轨道（autoparser PR / llama.cpp v1.0.0 / 标准化 eval /
工具面裁剪）不插队，与脑结构无关。

## Consequences（后果）
- 正面：总线的边际成本递减——新增机制只注册字段，不用改每个消费者；
  中期目标接上去就是填字段，避免"先做中期再推倒重接"。
- 负面：GWT 改动触及三个核心消费者（控制回合/Critic/审计），一旦出错影响面广——
  因此坚持"行为等价改造"（保留原字段写入，只改读取来源）+ 全量回归门禁。
- 实测教训（FEP）：初版 FEP 偏差走 `pendingInject` 注入，消耗 turnInjections 额度，
  导致 D5 审计被预算挡住（"连续失败却不审计"）→ 改为只记 trace + pendingLearn 学习队列，
  **不占运行时注入通道**；即时纠偏仍归 verify-on-stop/D2。这是"学习信号 ≠ 运行时干预"的边界案例。
- 验证：GWT 9/9 + FEP 7/7（共 16/16）；全量 101 PASS / 0 FAIL；回归 30/30；config 一致。
