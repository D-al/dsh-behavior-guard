# Skills 双轨受控重复实验报告（2026-11-22 第二版）

> 触发：用户"做受控重复实验：同任务 × 每模式 ≥2 次 × 任务轻量化（只测工具选择不写报告），严格等任务自然结束"
> 相对第一版（docs/SKILLS_AB_RESULT_20261122.md）修正：新会话每次重建、轻量任务、严格自然结束判据、样本均衡

## 一、实验设计

| 项 | 设计 |
|---|---|
| 模式 A (ON) | 默认 `skillsEnabled: true`，关键词命中即注入技能卡 |
| 模式 B (OFF) | 运行版 cordis.patch.yml 加 `skillsEnabled: false`，官方 skill 工具保留 |
| 场景 common | "用 glob 列 test_*.py 文件，直接告诉我数量"——1 步工具调用，不写文件 |
| 场景 rare | "用 pwsh 查有没有 llama-server 进程（排查卡死/OOM 第一步）"——命中 `debug-llama-server` 关键词 |
| 每格样本 | ≥2（实际 ON/common 4、ON/rare 2、OFF/common 3、OFF/rare 2）|
| 会话隔离 | **每个 run 新建会话**——技能卡 per-session 只注入一次，同会话第二次会假阴性 |
| 自然结束判据 | `turn/end(reason.kind=completed)` 出现；超时 180s 记失败 |
| 证据源 | **会话文件 session.v4.jsonl.zstd**（bridge events 有分页截断，不可靠）|

## 二、结果（权威统计，从 11 个会话文件重建）

| 模式 | 场景 | n | inject 均值 | 工具调用均值 | 自然结束 | 工具选择 |
|---|---|---|---|---|---|---|
| ON | common | 4 | **1.00** | 2.0 | 4/4 | glob×4（其中1次追加pwsh）|
| ON | rare | 2 | **1.00** | 1.0 | 2/2 | pwsh×2 |
| OFF | common | 3 | **0.00** | 2.3 | 2/3 | glob×3（其中1次追加pwsh×3，未结束）|
| OFF | rare | 2 | **0.00** | 1.0 | 2/2 | pwsh×2 |

（1 个 OFF/common 会话未自然结束：模型 glob 后又调 pwsh×3，被纠正器介入——保留为失败样本，不删）

## 三、结论

### 能下的结论（这次样本够）

1. **开关确实生效**：ON 每 run 注入 1 张卡、OFF 每 run 0 张——配置覆盖真实作用于运行时。
2. **两种轻量任务的工具选择在 ON/OFF 下完全一致**：
   - common 都是 glob（偶尔追加 pwsh），rare 都是 pwsh
   - **关键词技能卡注入没有改变工具选择**——至少在这两个场景、这个样本量下
   - 这是对"自研注入是否干扰常用工具"的直接回答：**没有观察到干扰**
3. **注入触发准确**：common 场景命中 `tool-boundaries`（因为任务提到 glob/test_*.py），rare 场景命中 `debug-llama-server`，都符合关键词设计。结合第一版"常用任务也误触发"的发现，说明关键词覆盖面宽，但**宽覆盖并未造成工具选择偏差**。

### 不能下的结论（诚实标注）

1. **不能证明注入"有用"**：因为 OFF 组工具选择一样好（都是 1 步完成）。注入既没帮上忙，也没帮倒忙——在这两个轻量场景里它是**中性**的。
2. **不能推广到复杂任务**：轻量任务 1 步就结束，没有给技能卡发挥作用的空间。第一版复杂任务（写报告）里模型也**没有调用 skill 工具读手册**（官方 skill 路径 0 调用），所以"注入到底有没有被模型用上"仍未验证。
3. **样本仍小**：每格 2-4 次，35B 单次波动大（有 2/11 会话陷入多步）。要提高置信度需每格 ≥5 次。
4. **runner 的 wait 判据有 bug（已记录）**：run 命令的 wait_natural_end 在部分会话漏记，所以最终统计**直接从会话文件重建**（`rebuild` 命令）——证据源是会话文件，不是 runner 日志。

## 四、净建议（相对第一版更新）

- 第一版建议"收窄 tool-boundaries 关键词"——本受控实验显示**注入并未改变工具选择**，所以误触发的代价可能只是几行 token，**收窄的紧迫性下降**；可做但不是必须。
- **不建议拆掉自研注入**：OFF 组没有更好，ON 组没有更差；且官方 skill 工具调用 0 次，主动路径未验证。保持现状是零风险选择。
- 若还想深挖，下一个实验应测**复杂任务下注入是否被模型真正读用**（看有没有 read 技能手册全文的动作），而不是简单任务的工具选择。

## 五、实验纪律
- dsh 按需：实验前 start、结束 stop；配置恢复原样（回滚点 `cordis.patch.before_skills_ab.yml`）；llama 残留 0
- 证据只认真实会话文件的 tool/call 与 turn/end 事件，不靠 trace 关键词计数
- 失败样本保留不删（OFF/common 1 个未结束会话计入统计）
