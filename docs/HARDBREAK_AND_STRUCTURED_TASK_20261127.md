# 调研 + 实现：结构化任务在论文与 harness 层怎么解（2026-11-27 00:35）

> 问题延续：机制全在工作但模型不服从 → 论文和社区怎么解？harness 有哪些手段？

## 一、论文核心答案：ACI（Agent-Computer Interface）

SWE-agent（NeurIPS 2024, arXiv 2405.15793）论文里的失败案例与我们的现场**几乎一致**：

> "智能体试图定位 `PVSystem`，却**陷入目录探索和反复出现的搜索结果中**"

**解法不是提示词，是重新设计接口**：

| ACI 设计 | 做法 | 我们对应的病灶 |
|---|---|---|
| 有界文件视图 | 每次只给 **100 行** | `read` 一次全文 → 反复读想"看全" |
| 搜索结果摘要 | 每次 ≤50 条，过多提示缩小范围 | grep 8 次仍无有效信息 |
| **lint 门控** | 语法错就**丢弃编辑**并附上下文 | 只有事后检查，编辑照样落盘 |
| 上下文折叠 | 保留最近 5 条观察 | 历史一直累积 |
| 空输出明确反馈 | "命令成功但无输出" | 可能让模型困惑 |

**量化**：GPT-4 Turbo + 纯 shell 11.00% → SWE-agent 18.00%（相对 **+64%**），**模型权重零改动**。

设计原则一句话：**"操作简单、多步合并、反馈简洁但信息充分、防止错误传播"**。

## 二、社区 harness 的 5 个手段

1. **断路器（Breaker）**：同一调用连续失败 N 次 → 自动停，交还给人。共识 N=3。
2. **Maker/Checker 分离**：社区列为"最大误区"——让生成代码的同一个模型判定完成，会共享盲点（自纠正研究：漏掉 64.5% 自己的错误）。Claude Code `/goal` 用**独立小模型**判定。
3. **硬门禁代替自述**：完成条件由测试退出码/构建结果/文件状态表达，不接受模型自述。
4. **预算封顶**：`--max-turns`、`--max-budget-usd`。
5. **降低工具粒度**：SWE-agent 的核心，也是我们最缺的（read 全文件、grep 返回大量上下文）。

## 三、Plan-and-Execute 的量化切换点

- **ReWOO**：token 降 **79.7%**，准确率反升 1.6pp
- **Planner's Dividend**（2026）：任务步数 **H > 13.8** 就该上规划器；可靠性 90% 时阈值降到 **8.0**

我们实测：1 行修改跑了 55 步 —— 远超 13.8，说明应该在首次 read 后就锁死计划。

## 四、落地实现：step 层硬中断（Breaker）

### 设计（三层）
```
L1: stepsSinceWrite >= 5  且  同一文件 read >= 3  → 注入强提示（1 次机会）
L2: 警告后 2 步仍无改观                            → kind:'reject' 硬停本轮
```

### 代码位置（两版同步）
1. 配置：`hardStepBreakEnabled / hardStepStreak: 5 / sameFileReadLimit: 3 / hardStepGrace: 2`
2. `tool/call`：记录 `readFileCounts`（Map<path, count>）
3. `agent/pre-step`：硬中断逻辑（在 mind_state 之后、control_turn 之前）
4. `turn/start`：重置 `readFileCounts` / `hardStepWarned`

### 实测结果（同任务对照）

| 指标 | 无硬中断（上一轮） | 有硬中断（本轮） |
|---|---|---|
| 工具调用 | **55 次** | **12 次** |
| trace 事件 | `step_hard_warn` 无 | step 11 warn（reads 3）、step 13 stop（reads 4） |
| 结束方式 | 手动 cancel | **自动 `TURN/END blocked`** |
| 产物 | 只改安装目录（双副本不一致） | **未改，两副本一致** |

**下降 78%，且避免了"改一半"的副作用。**

### 明确它不解决什么
- **不解决"做对"**：任务仍未完成，只是快速认输
- **不解决"理解"**：模型还是不知道 1100px 该改哪个文件
- 它只是**止损**，对应社区第 1 条（Breaker）

## 五、下一步（按 ROI，未做）

| 优先级 | 做法 | 依据 |

## 六、诚实边界

1. 单次对照（55 vs 12），有 ±10% 波动，但 4.5 倍差距量级可靠。
2. 阈值（5/3/2）是从社区 N=3 外推的，**未做独立标定**；可能误伤"合法需要多次读"的任务（如多文件对比）。
3. `stepsSinceWrite` 在 streak 检查时已达 10（非 5），因为 read 计数条件后满足 → 实际触发点是 read≥3。
4. ACI 的"有界读"我们**改不了工具本身**（那是 dsh 的 read），只能在 harness 层做事后提示，效果弱于原版。
5. 55 次那轮是"任务过小反而更易空转"的场景，不能外推到所有任务。
