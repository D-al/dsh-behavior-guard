# 实测：35B 有反思倾向吗？（2026-11-27 12:05）

> 用户问题："那模型本身有反思倾向吗？"
> 这不是推测题。本文用 **53 个真实会话 / 1400 条 assistant 思维链**做了直接测量。
> **结论：有，而且很强——但它的反思几乎全部被 harness 丢弃了。**

## 一、测量方法

数据源：`D:/Brain/dsh-data/sessions/**/session.v4.jsonl.zstd`（近 7 天，53 个会话），
用 `dump_session.mjs` 解压后逐条扫 `assistant/message` 的 `text`/`thinking`/`reasoning` block。

四个宽口径正则：
- 自我质疑：`等等|等一下|让我重新|不确定|先确认|我怀疑|再想想`
- 明确反思：`反思|复盘|回顾|总结经验|我意识到|我发现自己|下次应该`
- 发现错误：`我错/搞错/想错|不对，|有问题|原来…不是`
- 修正意图：`改成|改回|换回|应该是|重新试|换一种方法`

## 二、核心数据

| 指标 | 数值 |
|---|---|
| assistant 消息（含思维链） | 1400 条 |
| 有反思语句的会话 | **46 / 53（87%）** |
| 自我质疑 | **626 条（44.7%）**；每会话中位 9 次，最大 129 |
| 修正意图 | 334 条（23.9%） |
| 发现错误 | 135 条（9.6%） |
| 明确反思 | 118 条（8.4%） |
| 反思后 3 步内有工具调用 | 786 / 808（**97%**） |
| 反思后工具参数改变 vs 原样重试 | **169 : 17（10:1）** |

**解读**：模型不只是"会反思"，而是**反思后真的会改行为**——参数改变率是原样重试的 10 倍。
这才是"从错误中学习"的微观证据，而且发生在**没有任何错题本、没有 recall 工具**的当前架构下。

## 三、最关键的对照：谁触发了反思

对 245 条反思样本回溯前序事件：

| 触发来源 | 数量 | 占比 |
|---|---|---|
| 工具结果后（对失败的被动响应） | 126 | **51.4%** |
| **harness 注入后** | **0** | **0.0%** |
| 自发 / 普通用户消息后 | 119 | **48.6%** |

**harness 注入 0% 是本次最反直觉的发现**：控制回合、critbank、review echo、经验沉淀等
所有注入加起来，**没有一次真正激发出反思语句**。

结合上一份诊断（`REFLECTION_RECALL_GAP_20261127.md`）：
- 模型**不缺反思倾向**（44.7% 自我质疑）
- 缺的是**反思被看见、被记住、被复用**的通道
- harness 的注入不是"教会它反思"，而是**在它已经反思完之后才出现**——时序错位

## 四、对项目旧结论的修正

项目长期结论："**不能依赖模型的元认知（小模型只搜 20% 该搜的）**"——这条需要限定适用范围：

| 维度 | 旧结论是否成立 | 数据 |
|---|---|---|
| 模型会不会**自发产生**反思/纠错语句 | ❌ **不成立**——会，且频繁 | 87% 会话、44.7% 自我质疑 |
| 反思后会不会**改行为** | ❌ **不成立**——会，10:1 | 169 改参数 vs 17 原样 |
| 模型能不能**准确判断自己缺什么知识** | ✅ 仍成立 | 只搜 20% 该搜的（外部调研） |
| 能不能**依赖模型自己决定何时反思并沉淀** | ✅ 仍成立 | harness 注入激发反思 0% |
| 反思内容**质量是否可靠** | ✅ 仍成立 | 论文：无外部反馈反思把 GSM8K 95.5→89.0 |

**修正后的表述**：
> 模型有强烈的**反思行为倾向**，且反思后确实改行动；但它**不会可靠地评估自身知识缺口**，
> 也**不会因为被提示就自动产出可沉淀的经验**。所以规则驱动仍必要，
> 但方向应从"替代模型反思"改为"**接住模型已有的反思**"。

## 五、这直接改变错题本的设计优先级

上一份错题本文档建议 P0 是"加 trace 观测基线"。本数据把它进一步收敛：

**不需要先造反思，需要先接住反思。**

1. **最高优先级**：把 `s.last.reasoning` 里已有的纠错/反思句**宽正则捕获**（现在 `CORRECTION_RE` 太窄，
   要求"改回/恢复/撤销"等具体措辞，导致 `open_correction_captured: 0`，但
   `open_correction_survived_compaction: 14` 证明句子确实存在）
2. 捕获后不必立刻进 critbank（质量不可靠），先进 `_pending_learn` 候选区 + 外置验证
3. **不要加热路径反思工具**——模型已经在反思了，缺的是漏斗不是动机；
   加工具反而触发论文里的 overthinking / 改错答案风险
4. harness 注入时机应**前置到反思之前**（现在全在之后），否则永远是马后炮

## 六、样本偏差（诚实边界）

- 53 个会话里大量是**同一个硬件监控插件开发任务**的多轮续接，"自我质疑"高可能部分来自该任务的
  反复调试性质（PowerShell 语法错、WMI 取不到数）
- 按会话去重后，"明确反思"中位数降到 **0**（均值 2.6、最大 54）——说明反思高度集中在少数困难会话，
  不是均匀常态
- "自我质疑"中位数 9，说明它确实是稳定行为模式
- 正则匹配是**文本近似**，不等于认知意义上的"反思"；`等等/让我重新` 可能只是计划调整
- 参数改变 169:17 未区分"改对了"还是"改错了另一个错"，不能当作效果证明

## 七、一句话结论

**模型有反思倾向，而且反思后真的改行为；harness 完全没接住这份倾向（注入激发反思 0%、反思产物被丢弃）。**
下一步最高杠杆不是"教会它反思"，而是"给它一个能被看见、能被验证、能被复用的反思出口"。
