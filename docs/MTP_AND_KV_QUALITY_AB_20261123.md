# MTP 工具调用 + KV cache 精度 双验证（2026-11-23 晚）

> 用户："试一试这两件事"——① MTP 是否损害工具调用 ② KV q4_0→q8_0 是否改善质量

## 一、MTP 对工具调用准确率：**无显著损害，保留 MTP**

### 1.1 测试设计
自建 21 题工具调用基准（`tools/toolcall_bench.py`），5 类：单选 5 / 不该调用 3 / 参数精确 5 / 多工具 4 / 歧义 4。判分：工具名 + 参数关键字段 + "该不该调用"决策。

### 1.2 两轮结果（关键：第二轮推翻第一轮）
| 轮次 | MTP on | MTP off | 差值 |
|---|---:|---:|---:|
| 第 1 轮（21 题 × 1 次，严格判据）| 13/21 = 61.9% | 17/21 = 81.0% | **−19.1pp** |
| 第 2 轮（21 题 × 2 次，严格判据）| 30/42 = 71.4% | 29/42 = 69.0% | **+2.4pp** |

**第 1 轮的"MTP 损害 19pp"是小样本噪声，第 2 轮直接反转。**

宽松判据（歧义题允许多个合理工具）重判第 1 轮：
- mtp_on 19/21，决策错误 2 次（a4、e4"该调未调"）
- mtp_off 21/21，决策错误 0 次
- 第 2 轮宽松重判：两者各 1 次决策错误，**持平**

### 1.3 结论
- **没有可信证据表明 MTP 损害工具调用**。社区 protolabs 的 "function-calling 掉 40%" 未复现
- 保留 `MTP on`（decode +8%），不因质量担忧关闭
- **方法论教训**：21 题基准 + 每题 1 次的波动可达 ±20pp。判优必须多次重复（这次第 2 轮及时纠偏，否则会错误关闭 MTP 损失 8% decode）

## 二、KV cache q4_0 → q8_0：**质量无差别，保持 q4_0**

### 2.1 显存可行性
| 配置 | KV buffer | VRAM used | 能否启动 |
|---|---:|---:|---|
| V=q4_0（当前）| 780 MiB | 7744 MiB | ✅ |
| V=q8_0 | 1020 MiB（+240）| 7723 MiB | ✅ |

q8 能启动，没爆显存（96K ctx + 1350 MiB MoE cache 共存）。

### 2.2 质量：needle-in-haystack（48K 上下文，5 个深度）
| 配置 | 结果 |
|---|---|
| q4_0 | **5/5** |
| q8_0 | **5/5** |

社区 DuoNeural 报告"q4 让 DeltaNet 状态失稳、长上下文劣化"——**在我们的实际任务上没复现**。

### 2.3 测试踩坑（3 轮才测准）
1. 第 1 轮用裸 `/completion`：输出英文 `<think>`，全 FAIL——没套中文 chat template
2. 第 2 轮改 chat 接口但 `max_tokens=256`：中文思维链吃光预算，content 为空，q4 3/5 vs q8 2/5（假差异）
3. 第 3 轮 `max_tokens=1024`：两配置都 5/5，公平比较

**再次印证：`max_tokens` 不足造成的"答案区域为空"会被误判成质量差异。**

## 三、结论与生产状态
- **MTP：保留**（无质量证据支持关闭）
- **KV：保持 q4_0**（q8 白占 240 MiB 且无质量收益）
- 生产已恢复：share=1.0 / cache 1350 / NCMOE 40 / V=q4_0 / MTP on，health 200
- 两件事都没有触发配置变更——这是"测完发现现状就是最优"的结果

## 四、方法论沉淀
1. **小样本 A/B 必须重复**：21 题 × 1 次的 MTP 测试给出 −19pp，重复后变成 +2pp。任何单次差异 >10pp 的结论都要先怀疑测试设计
2. **判据要匹配任务**：歧义题用唯一期望工具判分会放大差异；宽松判据更贴近真实
3. **max_tokens 要够**：思维链模型在 needle 任务上会吃掉大量预算，256 不够
4. **裸 /completion vs chat 接口**：前者不套 template，中文锚点失效，测出来的是另一个模型行为
