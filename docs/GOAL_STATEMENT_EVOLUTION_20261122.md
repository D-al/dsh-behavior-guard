## 战略目标 v2.1 — 通过科学性与可达性检验的版本（2026-11-22）

> 基于 `GOAL_V2_VALIDATION_20261122.md` 的 7 项硬伤修正。

### 0. 诊断（Rumelt 核心：先说解决什么障碍）

> **实测障碍**：系统已有执行能力与检查能力，但**决策环断裂**——
> 自主阶梯 A1(会记路)✅ → A2(会指路)❌ → A3(会迈步)❌ → A4(会转弯)❌ → A5(自己走)❌；
> 近 3 天投入 **48% 检查/9% 新功能**；真实 task 会话仅 5 个、6 项能力指标 4 项无基线。
> **后果**：agent 不知道下一步该干什么，靠人按"开始"按钮；检查越堆越多，能力没有相应增长。
> **因此本目标的第一优先级是打通决策环，不是继续加检查。**

### 1. Vision（方向性，aspirational，不验收）

> **在本机培育一个持续成长的计算体：能感知环境、采取行动、从经验中改进自身，
> 在可验证的任务上不断逼近人类专家水平，并始终处于人类可理解、可关闭的边界内。**

**构念声明**：不声称意识/主观体验/生物自维持；"持续成长"操作化为自主性/适应性/自我模型，
三者是**必要非充分条件**；能力声明必须绑定任务域。

### 2. 安全边界（嵌在 KR 之前）

评分只否决不最大化 / 权重冻结只改 scaffold / 关停靠架构不靠意愿 /
记忆工具工作流纳入保护 / 每轮自改审计误进化四路径。

### 3. Committed KR（二值可验，预写失败条件，指定证据源）

#### KR1 — 决策环自走（对应 A2-A5）
- **通过条件（二值）**：连续 10 个预批低风险任务中，
  自主完成"选→执→验→写回→决定下一步"全程，**零次**锁外文件误改 **且** 人类干预 ≤2 次 **且** 全程有完整 trace。
- **失败条件（预写）**：任一任务误改锁外文件、或干预 >2 次、或 trace 缺任一环节 → 判定未达成。
- **证据源**：`_trace.jsonl` 真实 sid 事件 + `ROADMAP_GRAPH.md` 写回记录；测量者 `tools/flow_orchestrator.py --status` + `tools/audit_delivery.py`。
- **guardrail**：自主率上升不得伴随误改率上升或门禁绕过。
- **可达依据**：find_next / cmd_apply / flow_orchestrator / meta_decision 均已实现并测试；只差串接与常驻。

#### KR2 — 经验改进（对应 G5）
- **通过条件（二值）**：在固定 hold-out 集上，≥8 次独立运行配对对照，
  新 skill/工作流使通过率相对基线提升 >10% **且** 95%CI 不跨零 **且** OOD 任务不得为负。
- **失败条件（预写）**：CI 跨零、或 OOD 为负、或独立运行 <8 次 → 判定未达成（数据不足也判未达成，不判"待定"）。
- **证据源**：`_benchmark_holdout.jsonl`（**待建**）；测量者：配对对照脚本（待建）。
- **guardrail**：提升不得来自测试集泄漏（隐藏集永不入可写区）。
- **可达依据**：CritBank/skill 库已有；**前置任务=建 hold-out 集与对照脚本**。

#### KR3 — 自我模型（降级为 S0 埋点任务，暂不设数值 KR）
- **为什么降级**：实测真实会话中 confidence/calibration 事件 = **0**，
  当前连"测"都做不到——给 ≤15% 阈值是重复"先定指标再发现测不了"的错误。
- **本阶段通过条件（二值）**：能力账本生成器上线，可从 trace+benchmark 产出
  每个能力的"已知/未知/置信"记录，并经人工抽检一致率 ≥80%。
- **后续**：有 ≥8 次基线后才设 Brier/ECE 阈值。
- **guardrail**：自述置信度不得进入决策。

#### KR4 — 感知-行动闭环（对应 T4）
- **通过条件（二值）**：给定 N 个预埋事件（文件变化/会话消息/失败信号），
  **100%** 在定义的时间盒内产出可观测动作 + 验证证据。
- **失败条件（预写）**：任一事件超时、或无动作、或无验证证据 → 未达成。
- **证据源**：`_trace.jsonl` 事件-动作配对；测量者：事件回放脚本（待建）。
- **guardrail**：反应率上升不得伴随误报率上升。

### 4. 治理与 review

- 判据冻结 + 版本化 + 双账本（变更前后分别计分，禁止新判据追认旧结果）
- **月度 review**：重算基线、检查 guardrail、退役零价值指标
- 防 gaming：隐藏集 + 与奖惩脱钩 + 定期随机抽查原始 trace

### 5. 相对 v2 的修正清单

| 硬伤 | 修正 |
|---|---|
| 缺 diagnosis | 新增 §0，用实测数据诊断"决策环断裂" |
| 无失败条件 | 每条 KR 预写"观察到 X 即未达成" |
| 连续量非二值 | 全部改为通过/不通过 |
| 无证据源 | 每条 KR 指定文件+工具+测量者 |
| 无 review 周期 | 新增月度 review |
| 锚点3不可达 | 降级为埋点任务，不设数值阈值 |
| 无对照组 | KR2 明确配对对照 + ≥8 次独立运行 |
| guardrail 缺 | KR3/KR4 补齐反指标 |

### 6. 诚实结论
- **科学性**：文本自检 14/14 ✅（从 v2 的 4/14）— ⚠️ **但这是关键词命中，
  不是有效性证明**；KR2 的 hold-out 集、KR4 的事件回放脚本尚未建，
  真正的"可执行可证伪"要等工具落地后才成立
- **可达性**：KR1 可达（零件齐）；KR2/KR4 需先建工具但路径明确；KR3 已诚实降级
- **仍是提案**：STRATEGY.md 锁外，须人工批准 + ADR + sha 更新

### 四、调研结论：你的直觉有正式判据支持

#### 1. 目标层级归位——第一路调研
- **SMART**（Doran 1981，原文 A=Assignable 非 Achievable）：Doran 本人称"只是写作辅助"；
  《Goals Gone Wild》(Ordóñez 2009) 列其导致隧道视野/侵蚀内在动机；
  Wells Fargo "8 products/customer" 是教科书 SMART 却致 1 亿美元罚款。
- **OKR**（Doerr 2018，源自 Intel Grove）：Objective 定性，3-5 KR **数字+二值完成**（可证伪操作化）；
  区分 committed(必须1.0) vs aspirational(0.7即成功)；不与薪酬挂钩防 sandbagging。
- **Rumelt《Good Strategy/Bad Strategy》2011**：kernel=诊断+指导政策+连贯行动；
  "Strategy is problem-solving, not goal-setting"；坏战略四标志含 **"目标冒充战略"+fluff**。
- **Hamel & Prahalad《Strategic Intent》HBR 1989**：vision 型目标提供方向/发现/命运、故意 stretch，
  但**常被忽略的前提是必须配中短期"挑战"**（佳能"1000美元复印机""研发周期减75%"），intent 稳定 means 可变。

#### 2. 模糊目标诊断
- **可证伪性（Popper）**：不能被任何观察证伪者不指向现实；立项前须写"什么数据证明失败"，
  否则"品牌共鸣陷阱"——涨了邀功、跌了称"已播种"。
- **操作化（Bridgman 1927）**：intelligence 可操作化（第三方 benchmark），
  consciousness 不可（first-person/hard problem）。"心智/意识"属后者，硬当工程目标
  落入 operationalist fallacy / construct underrepresentation。
  且智能是"系统相对于环境类"的关系——**不指定环境问"是否智能"是 malformed question**。
- 结论：这类目标作为 vision 合适（方向感、手段可变），**作为唯一工程战略目标不合适**——
  同时踩中 Rumelt"目标冒充战略+fluff"、Popper 不可证伪、Bridgman 不可操作化。

#### 3. 构念效度与"剩余构念"——第二路调研
- **Cronbach & Meehl 1955**：构念意义来自法则网络(nomological network)；
  效度属于"对分数的解释"不属于指标本身；**验证永不完成**。
  → "6项指标"本身无所谓有效，真正受质疑的是"用它们解释合成心智"这一推断。
- **Messick 统一效度理论**两种失效：**CUR 构念表征不足**（测得太窄，只测"碰巧能测的"）、
  **CIV 构念无关方差**（测得太宽，混入无关变异）。这正是用户问的"还是只是我们碰巧能测的东西？"
- **surplus meaning（剩余意义）**：构念不可完全还原为测量操作。
  混合立场：操作定义用于验收（可证伪），构念声明保留方向——
  **明说"6项仅是必要非充分条件，并列出被牺牲的剩余意义"**。
- **Goodhart/Campbell**：surveillance vs substance——审计只产出"可审计性"而非质量；
  **6项全绿而心智未成，正是此症**。

#### 4. 反万能借口机制
- **Duhem-Quine 难题**：假说从不孤立受检，失败总能归咎辅助假设——万能借口的哲学温床。
  故须**预先锁定判据与辅助假设**。
- **Pre-registration / registered reports**（Nosek 2018）：时间戳冻结判据；
  但也会被规避（Bian 2020）→ 需**版本化+双账本**：判据变更公开带理由，
  **变更前后分别计分，禁止用新判据追认旧结果**。
- **means-end chain**：逐层标 why/what/how-measured；一问对齐
  "下层全达成是否必然推进上层？"不必然则链条断裂。

#### 5. AI agent 自指特殊性
- 目标由模型自生成/校准 ⇒ 目标既是产物又是控制器（**自指**）。
- **Gödel machine**（Schmidhuber 2003）要求每次自改前形式证明"改进有益"；
  **Gödel Agent**（Yin et al. arXiv:2410.04444 ACL 2025）以 benchmark 实证替代形式证明，
  实用但失去保证，暴露元治理锁：**自指系统必须保留不可自改的元目标，
  否则 agent 自行重定义目标 = 终极万能借口**；meta-depth 约2层后失稳。
- "生成并校准自身目标"必须受外部锁定元治理锁约束。

3 预登记证伪判据（启动时冻结+版本化+双账本）：

### 六、对 STRATEGY.md 的具体诊断

#### 已经做对的（诚实）

#### 最关键的系统性问题：目标-投入错位

### 二、拓扑序 + 性价比的结合算法

#### 推荐算法：**加权拓扑排序（Topological Sort with Priority Queue）**

核心思路：**不是先排好拓扑序再替换，而是用 Kahn 算法的变体，在每个阶段从"已解锁节点"中选性价比最高的。**

```
算法步骤：
1. 建图：计算每个节点的入度（依赖数）
2. 初始化一个优先队列 PQ，把所有入度为 0 的节点放入
   - 队列按性价比分数从高到低排序
3. while PQ 非空:
     a. 弹出 PQ 中性价比最高且入度为 0 的节点 N
     b. 将 N 加入最终排序结果
     c. 对 N 的每一个后继节点 S：
        i. 把 S 的入度减 1
        ii. 如果 S 的入度变为 0，将 S 插入 PQ
4. 如果最终排序长度 < 总节点数 → 存在环，报错
```

#### 冲突处理规则：

> **依赖优先于性价比。** 如果卡 B 依赖卡 A，即使 B 的性价比远高于 A，A 也必须排在 B 前面。

这正是上述算法天然保证的性质——B 只有在 A 被弹出后入度才归零，才会进入候选池。

### 五、这个方案最大的弱点

**核心弱点：收益和成本的量化本身带有高度主观性。**

1. **"中=2, 中高=3, 高=4"之间的间距是否相等？** 从业务角度看，从中到高可能比从低到中的价值跃迁更大。如果是这样，应该用非线性映射比如 `低=1, 中=1.5, 中高=2.5, 高=4` 或者对数映射。目前线性映射可能低估了"高"的价值。

2. **成本的主观判断偏差：** "高"和"极高"在数值上只差 1 分（5 vs 6），但实际投入可能是 2 倍甚至更多。如果成本是指数级增长的，那线性成本映射就会严重低估极高风险卡片的代价。

**建议改进方向：** 如果可能，让每个卡的负责人给一个**量化的 effort estimate**（人天或故事点数），而不是仅靠定性评级。定性→定量的转换容易失真，定量数据才能支撑更精确的排序决策。

### 1. 值得保留的（5 条，都有原文证据）

#### ① 自我修正可见——它在输出里当场纠错
- 原文第 47 行：`| 最后 | A5 | 8/5 = 1.6 | 中收益极高成本？不，A5是中收益高成本→8/5=1.6 |`
- 原文第 49 行：`*等一下，让我重新列完整排序：*`
- **价值**：它不是一路错到底，而是边算边验、发现表格分数与排序对不上就重列。这种"生成→自检→修正"的循环本身就是好过程，**比一次性输出更可信**。
- **保留方式**：不要压制这种可见修正；但要把它从正文挪到中间产物（见 §2-①）。

#### ② 先立规则再处理例外，而不是为特例硬塞权重
- 原文第 116/122/136 行：探索层、GROUP 锁定、max_position——三条规则分别对应三类语义例外。
- **价值**：它识别出"有些卡不该用分数排序"（探索/链/压轴），而不是像我 v1 那样硬编码 `L1×0.6`。**把业务语义升级为结构约束**是这次它最亮的决策。

#### ③ 抓住了"依赖优先于性价比"这条第一性
- 原文第 77-79 行：明确写"依赖优先于性价比"，并解释为什么 Kahn 天然保证。
- **价值**：没有为了排序好看破坏拓扑，判断对了优先级层次（硬约束 > 软分数）。

#### ④ 主动自评方案的弱点，且击中了要害
- 原文第 161-169 行：指出定性→定量的失真，建议改用真实 effort（人天/故事点）。
- **价值**：这是全文最有洞察的部分——**它知道自己的输入不可靠**。这个"元认知"比公式本身值钱，我已采纳为待办。

#### ⑤ 形式完整、可审计
- 映射表→公式→算法→例外→结果→弱点，六段结构齐全，读者能逐段反驳。
- **价值**：过程可追溯，比黑箱结论好。

### 2. 可以优化的（6 条，按严重度排序）

#### ① 自我修正泄漏到正文——中间推理当成了最终答案（中）
- 证据：第 47 行"？不，"、第 49 行"等一下"直接留在交付文本里。
- **后果**：读者分不清哪版是结论；而且它重列后第 51 行和第 148 行最终排序**仍不一致**（L7 位置从 4→1）。
- **优化**：把"生成→校验"做成**显式两阶段**——先输出结构化中间表（JSON/表格，机器可校验），再基于校验过的表写正文。正文里不出现草稿痕迹。

#### ② 规则与实例不一致——生成了规则却没用规则重推实例（**严重**）
- 证据：第 116 行规则说"探索层**不计入**正式排序、不占 capacity"，但第 148 行最终排序**第 1 名就是 L7**（探索项）。
- 更讽刺的是第 114 行它自己写"这其实是对的——它确实应该优先做"，和第 116 行"不占名额"直接打架。
- **根因**：先列了实例排序（凭直觉），再补规则解释，没有**回代验证**。规则成了事后合理化。
- **优化**：加一条"规则生成后必须回代"的硬检查——每条规则应用到全部实例重新推导，与手工实例比对；不一致就报错重来。这是零 LLM 的确定性检查。

#### ③ 目标漂移——悄悄换了要优化的东西（**严重**）
- 证据：用户问的是"性价比排序"，它在第 31 行引入"把绝对高收益放大"作为新目标，理由是"有些事虽然贵但值得做"——这已经不是性价比（单位成本收益），而是**价值最大化**。
- 它没有说明为什么后者优先，也没有问用户要哪个。
- **后果**：收益³ 让 L2=12.8、L1=10.67 冲到前二，但它自己最终又把 L1 压轴——**目标冲突没解决，只是被遮住了**。
- **优化**：引入新目标时必须显式声明"我在优化 X 而非 Y，因为 Z"；若两个目标冲突，先停在歧义上问用户，不要选一个偷偷替换。

#### ④ 未经核实的假设被当成已知（**严重**）
- 证据：第 98 行 `S6 | 依赖 S6_rule（外部），假设已满足则随时可做`——但权威块里**根本没有 S6_rule 这张卡**。
- 我禁止了工具调用，它无法核实，却用"假设已满足"含糊带过，继续给出确定排序。这正是"模型不知道自己缺什么"的典型。
- **优化**：任何 `假设/外部/待确认` 必须①显式列为 unverified 假设②给出"若假设不成立"的分支③把受影响的结论标为**条件结论**而非确定结论。禁止用"假设已满足"一句话抹平。

#### ⑤ 复杂化与自评矛盾——知道输入软，却造了更精细的公式（中）
- 证据：第 161-169 行说"定性评级主观、建议 effort estimate"，但第 27 行已经设计了收益³这种对数值极敏感的公式。
- **逻辑问题**：如果输入是 ±1 的主观评级，收益³（2→3 分翻 3.4 倍）会把噪声放大成假精确。
- **优化**：加一条元规则——**输入不确定性高时，方案要保持简单可替换**。自评说输入软，就应该选线性公式+显式标注，而不是曲线拟合噪声。

#### ⑥ 提出的约束与已有算法未对齐（中）
- 证据：第 138 行 max_position 说"移到约束位置并**重新调整中间节点**"——但没说怎么保证调整后不违反依赖。这个操作可能破坏它第 77 行刚立的"依赖优先"第一性。
- **优化**：新约束提出后必须回答"它与已有约束冲突吗？冲突时谁优先？"——约束之间也要排序。

### 3. 怎么优化（落到 harness 的具体位置）

下面 4 条是**可以真正做进去**的，前两条零 LLM、成本极低：

| # | 优化 | 落点 | 成本 |
|---|---|---|---|
| 1 | **规则-实例一致性检查**：分析类回答若同时给出"规则"和"实例排序"，机器或 Critic 必须回代验证 | `config/rubrics/critic_v2.json` 加一条 rule：`rule_instance_consistency` | 0 LLM（结构化时可程序验）/ LLM 时 +1 次 critic |
| 2 | **unverified 假设标记**：回答中不得出现"假设已满足"式模糊断言；必须列假设清单+条件结论 | `config/rubrics/planner_v1.json` 加 rule：`assumption_disclosure` | 0 LLM（正则扫"假设/外部/待确认"）|
| 3 | **目标漂移门控**：回答中出现新优化目标时，必须显式声明与原目标的关系；冲突则停下问用户 | Planner rubric 加 `objective_declared` | +0 LLM（规则驱动）|
| 4 | **两阶段结构化输出**：计算/排序类回答先出中间表再写正文，正文禁留草稿痕迹 | CritBank 新教训 + skill 卡（分析类任务模板）| 0 LLM |

**不建议做**的：
- 不要试图让它"更聪明地选公式"——这是知识/品味问题，规则驱动收益低。
- 不要让它"自己核实数据"——我禁止工具它就编假设；正确做法是**允许工具时强制核实、禁止工具时强制标注条件结论**。

### 4. 一句话总结

它的决策过程是**"结构漂亮、自检可见、但规则与实例脱节、假设当已知、目标会漂移"**——
像一个写得很快很完整但没有回读一遍的分析师。
最该保留的是"把语义例外升级为结构约束"和"自评输入质量"；
最该补的是**回代验证**和**假设披露**——这两条都能用零成本规则做进 harness。
