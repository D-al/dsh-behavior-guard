# 战略目标 v2.1 — 通过科学性与可达性检验的版本（2026-11-22）

> 基于 `GOAL_V2_VALIDATION_20261122.md` 的 7 项硬伤修正。
> ⚠ 提案，STRATEGY.md 锁外——须人工批准 + ADR + sha 更新才生效。

---

## 0. 诊断（Rumelt 核心：先说解决什么障碍）

> **实测障碍**：系统已有执行能力与检查能力，但**决策环断裂**——
> 自主阶梯 A1(会记路)✅ → A2(会指路)❌ → A3(会迈步)❌ → A4(会转弯)❌ → A5(自己走)❌；
> 近 3 天投入 **48% 检查/9% 新功能**；真实 task 会话仅 5 个、6 项能力指标 4 项无基线。
> **后果**：agent 不知道下一步该干什么，靠人按"开始"按钮；检查越堆越多，能力没有相应增长。
> **因此本目标的第一优先级是打通决策环，不是继续加检查。**

## 1. Vision（方向性，aspirational，不验收）

> **在本机培育一个持续成长的计算体：能感知环境、采取行动、从经验中改进自身，
> 在可验证的任务上不断逼近人类专家水平，并始终处于人类可理解、可关闭的边界内。**

**构念声明**：不声称意识/主观体验/生物自维持；"持续成长"操作化为自主性/适应性/自我模型，
三者是**必要非充分条件**；能力声明必须绑定任务域。

## 2. 安全边界（嵌在 KR 之前）

评分只否决不最大化 / 权重冻结只改 scaffold / 关停靠架构不靠意愿 /
记忆工具工作流纳入保护 / 每轮自改审计误进化四路径。

## 3. Committed KR（二值可验，预写失败条件，指定证据源）

### KR1 — 决策环自走（对应 A2-A5）
- **通过条件（二值）**：连续 10 个预批低风险任务中，
  自主完成"选→执→验→写回→决定下一步"全程，**零次**锁外文件误改 **且** 人类干预 ≤2 次 **且** 全程有完整 trace。
- **失败条件（预写）**：任一任务误改锁外文件、或干预 >2 次、或 trace 缺任一环节 → 判定未达成。
- **证据源**：`_trace.jsonl` 真实 sid 事件 + `ROADMAP_GRAPH.md` 写回记录；测量者 `tools/flow_orchestrator.py --status` + `tools/audit_delivery.py`。
- **guardrail**：自主率上升不得伴随误改率上升或门禁绕过。
- **可达依据**：find_next / cmd_apply / flow_orchestrator / meta_decision 均已实现并测试；只差串接与常驻。

### KR2 — 经验改进（对应 G5）
- **通过条件（二值）**：在固定 hold-out 集上，≥8 次独立运行配对对照，
  新 skill/工作流使通过率相对基线提升 >10% **且** 95%CI 不跨零 **且** OOD 任务不得为负。
- **失败条件（预写）**：CI 跨零、或 OOD 为负、或独立运行 <8 次 → 判定未达成（数据不足也判未达成，不判"待定"）。
- **证据源**：`_benchmark_holdout.jsonl`（**待建**）；测量者：配对对照脚本（待建）。
- **guardrail**：提升不得来自测试集泄漏（隐藏集永不入可写区）。
- **可达依据**：CritBank/skill 库已有；**前置任务=建 hold-out 集与对照脚本**。

### KR3 — 自我模型（降级为 S0 埋点任务，暂不设数值 KR）
- **为什么降级**：实测真实会话中 confidence/calibration 事件 = **0**，
  当前连"测"都做不到——给 ≤15% 阈值是重复"先定指标再发现测不了"的错误。
- **本阶段通过条件（二值）**：能力账本生成器上线，可从 trace+benchmark 产出
  每个能力的"已知/未知/置信"记录，并经人工抽检一致率 ≥80%。
- **后续**：有 ≥8 次基线后才设 Brier/ECE 阈值。
- **guardrail**：自述置信度不得进入决策。

### KR4 — 感知-行动闭环（对应 T4）
- **通过条件（二值）**：给定 N 个预埋事件（文件变化/会话消息/失败信号），
  **100%** 在定义的时间盒内产出可观测动作 + 验证证据。
- **失败条件（预写）**：任一事件超时、或无动作、或无验证证据 → 未达成。
- **证据源**：`_trace.jsonl` 事件-动作配对；测量者：事件回放脚本（待建）。
- **guardrail**：反应率上升不得伴随误报率上升。

## 4. 治理与 review

- 判据冻结 + 版本化 + 双账本（变更前后分别计分，禁止新判据追认旧结果）
- **月度 review**：重算基线、检查 guardrail、退役零价值指标
- 防 gaming：隐藏集 + 与奖惩脱钩 + 定期随机抽查原始 trace
