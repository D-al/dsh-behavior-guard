## 蒸馏原则（社区大项目做法）

原始日志（逐日、流水账、含失败与试错）→ **历史说明书**（按主题、只留决策与结果）→ README（一句话结论）。
三层各司其职：
- 原始日志：完整的试错过程，不可删（逢疑可查）
- 本目录：提炼后的"发生了什么、为什么、结果如何"
- README/ADR：结论与不可变决策

## 五层涌现逻辑（本目录的组织骨架）

> **这不是按时间切的分期，是按依赖链切的层级。** 时间是表象，依赖是本质。
> 每一层都是下一层的**必要前提**——跳过任何一层，后面都建不成。
> 理解这条链，才能理解我们为什么按这个顺序做事、为什么有些"看起来更酷"的方向被推迟。

| 层 | 名称 | 核心问题 | 关键产出 | 时间 |
|---|---|---|---|---|
| **1** | **物质基础** | 能不能在本地跑起来？ | llama.cpp 引擎 + Q4 权重 + SearXNG + 8G 边界确认 | 10-13～10-19 |
| **2** | **调优基础** | 能不能稳定跑、跑多快？ | 显存账 / q8_0 KV / 温度 U 形 / 投机解码；证伪 decode 伪优化 | 10-20～11-06 |
| **3** | **构建脑** | 模型为什么会行为退化？怎么补？ | 「只输出好」回路 → L0-L3 / 海马体 / 前额叶 / 免疫系统 | 11-07～11-17 |
| **4** | **合成心智** | 器官怎么整合成一个整体？ | 三角色 / 控制回合 / 两仓合并 / `D:/Brain` 独立域 | 11-17～11-18 |
| **5** | **进一步探索** | 心智会不会更新自己？ | 心智拼图 P0-P2 / 6 路调研 / 社区对比 / ADR 与文档架构 | 11-18～ |

### 依赖关系的实证

- **1→2**：先有引擎和权重，才谈得上显存/温度/量化调优——没有 8G 跑 35B 这个硬约束，第 2 层所有决策都无意义
- **2→3**：调优中发现的"提前 EOS / 复读退化 / 思维链锚点敏感性"，正是第 3 层行为器官要解决的问题；
  而且没摸清显存账就外置器官，会直接撞天花板
- **3→4**：先有"守卫是免疫细胞、脑区是外置器官"的方法论，才有把它们整合成"合成心智"的概念跃迁
- **4→5**：心智成形后，才有意义问"它缺什么拼图、会不会从经验中变聪明"——这正是今天的探索

### 这条链如何指导未来（写进 [ROADMAP](../../ROADMAP.md)）

- 短期目标仍在**第 5 层**（标定阈值、去同源、test-time 自适应）——因为前 4 层已夯实
- 但第 5 层的"可控遗忘/技能闭环"必须回头依赖第 3 层的 CritBank 和第 2 层的验证文化
- 长期目标（GWT 总线、FEP 闭环）是第 4 层的深化——不是加新器官，是让器官间流动起来
