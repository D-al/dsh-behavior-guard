# 路线图改为纯卡片自动渲染（2026-11-20）

> 用户："性价比速查表和卡片详情脱节，我希望由每张卡自动组成性价比速查，或者把性价比速查融合进卡片详情；我希望路线图是纯粹由卡片自动实时组成和更新的。"
> 用户选了"两者都要"——自动速查表 + 卡片详情，都由同一份卡片字段渲染。

## 1. 改造前的问题

- §2 性价比速查表是**手工表**，M8/A1 完成后没更新（标着旧状态、A1 根本不在表里）
- 卡片详情（HUMAN_CARDS 自动块）和速查表**两个来源、互不同步**
- §4 中期表、§5 长期表也是手工表，与卡片详情第三处脱节

## 2. 单一真相源设计

**卡片（CAPABILITY_LADDER.yaml）是唯一语义源，ROADMAP_GRAPH.md 是唯一状态源。**
ROADMAP.md 的三个自动块全部从这两源渲染：

| 自动块 | 内容 | 数据源 |
|---|---|---|
| `HUMAN_PROGRESS_BEGIN/END` | 进度表（done 卡 + 下一项）| GRAPH 状态 + LADDER 标题 |
| `HUMAN_QUICKREF_BEGIN/END` | **新**：性价比速查（收益/成本/依赖/解锁/建议/状态，按 rank 排序）| LADDER 卡片字段 + GRAPH 状态 |
| `HUMAN_CARDS_BEGIN/END` | 卡片详情（做什么/为什么/好处/坑/反思/停 + **新增性价比/依赖→解锁两行**）| LADDER 语义 + GRAPH 状态 |

### 新增的卡片结构化字段

给 41 张卡补了 4 个字段：
- `rank`：排序（15 张从原 §2 表人工判断导入；26 张由 risk/tier 推导并标 `rank_derived: true`）
- `benefit`：收益（人工值或推导）
- `cost`：成本（人工值或 risk 映射）
- `advice`：建议（人工值或按 status 生成）

同时修了 `unlocks`/`unlock` 名称错配（数据用 unlock、代码读 unlocks）——给 16 张卡补齐 `unlocks` 镜像。

## 3. 手工表处理

- **§2 手工速查表** → 替换为 `HUMAN_QUICKREF` 自动块（保留 §2.1 逻辑关系链和各段叙述，它们是方法论、非状态）
- **§4 中期表 / §5 长期表** → 删表，改一句导航："本节卡片已收进 §2 自动速查表，深度信息见卡片详情"
- **§7 归档表 / §8 明确不做表** → 保留手工（归档历史 + 证伪清单，不是卡片状态）

## 4. 刷新入口

`roadmap_check.py --refresh`：只重渲染 ROADMAP.md 的三个自动块，**不改任何卡片状态**。
- `--apply` 在有 doing 卡写回时也会顺带刷新全部块
- `--refresh` 是平时改完卡片后的显式刷新入口，实现"实时更新"

## 5. 实证：卡片驱动速查表

```
改 CAPABILITY_LADDER.yaml 里 M2 的 benefit → "测试收益X" → --refresh
  → 速查表 M2 行立刻显示 "测试收益X"
恢复 benefit → "中" → --refresh → 速查表恢复 "中"
```
证明速查表**完全由卡片字段驱动**，零手工副本、零脱节。

## 7. 沉淀的教训

脱节的根因永远是"同一信息有多个手工副本"。解决方案不是同步，而是**消除副本**：
让所有视图从单一源渲染。改造时保留"人工 adjudicate 的值"（从旧表导入卡片），
而推导值必须显式标注（`rank_derived`），避免把推导伪装成人工判断。
