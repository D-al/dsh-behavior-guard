# 牺牲视觉的 557 MiB 给谁最划算：MoE cache vs DFlash 侧车（2026-11-24 早）

> 用户问：拆掉视觉编码器牺牲多模态，把侧车装上去，能提升多少？如果不用侧车、改给专家缓存，又能提升多少？

## 结论先说：**两者都不如"单纯释放显存"**

| 557 MiB 的用法 | 实测 tps | 相对基线 |
|---|---:|---:|
| **禁用视觉，显存空着** | **25.96**（n=14） | **+4.9%（显著）** |
| 禁用视觉，全给 MoE cache（1900 MiB）| 25.28（n=6） | +2.2%（且低于空着）|
| 禁用视觉，装 DFlash 侧车 | 11.98 / 16.25 | **−52% / −34%** |
| 基线：视觉 + cache 1350 | 24.74（n=12） | — |

**禁用视觉本身能提速 4.9%，但把省下的显存给 cache 或侧车都不会更好——反而更差。** 收益来自"显存余量跨过安全线、消除换页"，而不是来自"多缓存了专家"或"多了一个 drafter"。

---

## 一、实验设计（分离变量）

三个变量：视觉开/关、cache 大小、DFlash 开关。逐个 A/B，每组 6-8 次取中位，每次独立重启（清 cache 状态）。

## 二、数据

### 2.1 视觉开关 + cache 大小

| 配置 | 各次测量 | 中位 | 均值 | n | sd |
|---|---|---:|---:|---:|---:|
| 视觉 + cache 1350（基线）| 24.56, 24.91 | 24.74 | 24.74 | 12 | ~1.2 |
| **无视觉 + cache 1350** | 25.67, 26.25 | 25.96 | 25.96 | 14 | ~1.0 |
| 无视觉 + cache 1900 | 25.28 | 25.28 | — | 6 | 1.21 |

**无视觉 vs 基线：+1.22 t/s = +4.9%**，t ≈ 2.79（p<0.01，显著）。
**cache 1900 vs cache 1350（都无视觉）：−0.68 t/s**，反而略降（噪声内，但至少零收益）。

### 2.2 DFlash 侧车（上一轮已测，此处并列）

| 配置 | tps | 相对基线 |
|---|---:|---:|
| DFlash 全 CPU（ngl=0）| 11.98 | −52% |
| DFlash 半 GPU（ngl=3）| 16.25 | −34% |

侧车 736 MiB BF16，即使禁用视觉（腾出 906 MiB）能全放 GPU（余 170 MiB，贴近必卡阈值 186），按 ngl=0→3 的 +35% 斜率外推，极限也就 21-23 t/s，仍低于 MTP 的 24.7。

## 三、为什么"禁用视觉"能提速 4.9%

**不是视觉计算本身慢（文本推理根本不走视觉），而是显存余量跨过了安全线。**

| 状态 | 显存余量 | 现象 |
|---|---:|---|
| 视觉开（基线）| **349 MiB** | 低于安全线 450，**偶发 WDDM 换页** → 测量里出现过 22.3 t/s 的掉速，sd 1.69 |
| 视觉关 | **906 MiB** | 远离安全线，无换页 → 波动小（sd 0.47-1.31）|

这与之前记录的规律完全一致：**"空闲 ≥450 MiB 才安全；186 MiB 必卡（WDDM 换页→1~2 t/s）"**。基线在 349 MiB 处处于"轻微换页"的灰色地带——平均损失约 5%，偶尔掉得更狠。

## 四、为什么给 cache 没用

MoE cache 从 1350 → 1900（+41%）**没有提速**，说明：

- **专家访问是长尾分布**：热点专家早就被 1350 MiB 覆盖了，新增的 550 MiB 缓存的全是冷门专家，几乎不命中
- 这也印证了之前的判断"1350 MiB 已接近上限"
- 加大 cache 还可能有副作用：更大的分配块 → 显存碎片略增，抵消了微小收益

**要真正提高命中率，需要的是"把热点专家按访问频率精确排序"（LRU 已接近最优），而不是"无脑加大容量"。**

## 五、为什么给侧车更差

DFlash 侧车 736 MiB 的读取量，在 CPU 上要和主模型抢同一条 DDR 带宽（25 GB/s，我们最稀缺的资源）。而 DFlash 的 block=16 让验证时要处理最多 16 个 token → MoE 每 token 路由不同专家 → 最多读 128 个专家（MTP nmax=5 只需 40 个）。**draft 抢带宽 + 验证成本线性增长，双重挤压。**

## 六、建议

### 如果不需要看图 → 禁用视觉，白拿 5%
```bash
# .env 里清空（同时要注释 preset 里的 mmproj 行——两处都要改）
LLAMA_35B_MMPROJ=
```
收益：**+4.9% 且更稳**（sd 从 1.69 降到 ~1.0）。**不要**顺手加大 cache 或装侧车。

### 如果需要保留多模态 → 维持现状
当前余量 349 MiB 虽在安全线下，但平均只损失 ~5%，可接受。若想两全，可考虑：
- 把 mmproj 从 F16 降到 Q8_0（省约 280 MiB）——收益约为禁用视觉的一半
- 或降低 ctx（60K 省 292 MiB），但会提前触发压缩

### 不要做的事
- ❌ 加大 MoE cache（零收益）
- ❌ 装 DFlash 侧车（负收益）

## 七、一句话

**牺牲视觉能换来 +4.9%，但这个收益来自"显存别太挤"，而不是"腾出来给谁用"——给 cache 没用（热点已饱和），给侧车更糟（抢 DDR 带宽）。最优解是腾出来就空着。**
